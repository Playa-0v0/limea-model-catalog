# 推理档位合并表（待写清单）

> 来源：`Downloads/1.md` 与 `Downloads/2.md`（两份由不同模型做的文档级人工核查）交叉比对而成。
> **原则：取交集。两版结论冲突的行一律留 unknown，不猜。**
> 两份都是**公开文档检索、零 API 实测**，因此「可写」仅代表文档口径一致，不等于接口已实测通过。
> 只覆盖原表 81 个「需要人工 = 是」的行；其余 97 行上游已给档位，不在本表范围。

## 状态定义

| 状态 | 含义 | 落库处理 |
|---|---|---|
| 一致·可写 | 两版结论相同，且至少一版为「官方明确 / 已确认」 | 按合并结论写入 |
| 一致·低置信 | 两版同向，但都只是「系列推断 / 预计」 | 写入但标注低置信，待实测 |
| 一致·待实测 | 两版都判「待实测 / 无法确认」 | 留 unknown，列实测队列 |
| 分歧·留 unknown | 两版给出**互相冲突**的具体结论 | 留 unknown，进人工决断 |

## 落库字段（对应已批准的 schema 扩展）

- `form`（控制形态）：`effort`（离散档位）/ `toggle`（开关）/ `budget_tokens`（Token 预算）/ `forced`（强制推理）/ `none`
- `canDisable`（能否关闭）：`yes` / `no` / `unknown`
- 关闭方式与参数名只放维护数据（`source`），不进产物。
